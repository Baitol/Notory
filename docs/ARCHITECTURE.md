# Архітектура додатку Notory 🏛️

У цьому документі описано загальну архітектуру додатку **Notory**, взаємодію між його компонентами, життєвий цикл додатку та ключові інженерні рішення.

---

## 1. Архітектурний патерн: Багаторівнева архітектура (Layered Architecture)

Додаток спроєктовано за принципами чистої багатошарової архітектури з розділенням обов'язків (Separation of Concerns):

1. **Presentation Layer (Шар відображення / UI)**:
   - Знаходиться у `lib/screens/`.
   - Складається з віджетів Flutter (`ConsumerWidget`, `ConsumerStatefulWidget`), які відповідають лише за рендеринг інтерфейсу користувача та реакцію на дії (натискання, введення тексту, відкриття діалогів).
   - Не містить прямих SQL-запитів чи низькорівневої логіки роботи з файлами.
   
2. **State Management Layer (Шар управління станом)**:
   - Знаходиться у `lib/providers/`.
   - Реалізований за допомогою бібліотеки **Riverpod** (`flutter_riverpod`).
   - Центральний клас — `ReportsNotifier`, що успадковує `StateNotifier<List<ReportWithNotes>>`.
   - Зберігає поточний стан додатку в пам'яті, реагує на події від UI, викликає методи сервісного шару та розсилає оновлений стан усім активним віджетам.

3. **Service Layer (Сервісний шар бізнес-логіки)**:
   - Знаходиться у `lib/services/`.
   - Клас `DatabaseService` інкапсулює бізнес-правила:
     - Об'єднання звітів із відповідними замітками через SQL JOIN.
     - Забезпечення атомарності складних операцій за допомогою транзакцій (`_db.transaction`).
     - Очищення осиротілих записів (orphan cleanup) при видаленні зв'язків.

4. **Data Access Layer / Persistence (Шар даних та персистентності)**:
   - Знаходиться у `lib/models/`.
   - Використовує **Drift** — типобезпечну ORM-бібліотеку для роботи зі SQLite в екосистемі Dart/Flutter.
   - Клас `AppDatabase` керує схемою таблиць (`Notes`, `Reports`, `ReportNotes`), міграціями та підключенням до фізичного файлу `notory.sqlite`.
   - Операції читання/запису виконуються у фоновому ізоляті Dart (`NativeDatabase.createInBackground`), що запобігає будь-яким затримкам та блокуванню головного потоку рендерингу (UI thread).

## 2. Ініціалізація додатку та Bootstrap Lifecycle

Точка входу додатку — функція `main()` у файлі `lib/main.dart`:

```dart
void main() async {
  // 1. Ініціалізація зв'язки Flutter Engine з нативною платформою
  WidgetsFlutterBinding.ensureInitialized();

  // 2. Створення екземпляра бази даних SQLite (Drift)
  final db = AppDatabase();

  // 3. Створення сервісу бізнес-логіки
  final dbService = DatabaseService(db);

  // 4. Запуск кореневого дерева віджетів у середовищі Riverpod
  runApp(
    ProviderScope(
      overrides: [
        // Впровадження створеного сервісу в дерево залежностей
        databaseServiceProvider.overrideWithValue(dbService),
      ],
      child: const NotoryApp(),
    ),
  );
}
```

### Порядок ініціалізації:
1. `WidgetsFlutterBinding.ensureInitialized()`: гарантує готовність нативних каналів платформи до відкриття файлової системи через `path_provider`.
2. `AppDatabase()`: ініціалізує ліниву базу даних (`LazyDatabase`), яка відкриє файл SQLite за шляхом `getApplicationDocumentsDirectory() / notory.sqlite` при першому зверненні.
3. `DatabaseService(db)`: створює обгортку сервісу з доступом до бази.
4. `ProviderScope(overrides: [...])`: використовує патерн впровадження залежностей (Dependency Injection). Базовий `databaseServiceProvider` перекривається готовим екземпляром, що унеможливлює стан гонитви (race condition) і робить тестування простим.
5. При завантаженні `HomeScreen` спрацьовує `ref.watch(reportsProvider)`. Конструктор `ReportsNotifier` автоматично викликає `loadReports()`, який зчитує всі збережені звіти та замітки й миттєво показує їх користувачу.

## 4. Концепція Offline-First

Додаток повністю незалежний від підключення до мережі Інтернет:
- Усі дані (текст звітів, замітки, координати, часові мітки) записуються в локальний файл бази даних SQLite.
- Для мап використовується OpenStreetMap/ArcGIS тайли, які завантажуються через HTTP при наявності мережі, а при відсутності мережі інтерфейс додатку продовжує повноцінно працювати (нотатки фіксуються, координати записуються з супутників GPS).
- Немає обов'язкової реєстрації, аутентифікації чи серверного бекенду.

## 5. Дизайн-система та інтерфейс

Інтерфейс побудований на специфікації **Material 3** з фірмовою темною темою:
- **Основний фон**: темний сланцевий колір `0xFF0F172A` (Slate 900).
- **Поверхня карток та меню**: `0xFF1E293B` (Slate 800).
- **Акцентні кольори**:
  - `Colors.indigoAccent` — основні кнопки, активні елементи, полілінії маршруту на мапі.
  - `Colors.tealAccent` — геоприв'язка, мітки координат, статус-бейджи, підтвердження точок.
  - `Colors.redAccent` — деструктивні дії (видалення звітів чи заміток).
- **Типографіка**: Моноширинний шрифт для географічних координат (`fontFamily: 'monospace'`) для кращої читабельності десяткових часток градусів.
